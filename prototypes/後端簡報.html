後端負責範圍

這份文件要讓 PM 掌握什麼

本文件是給 PM／需求溝通用的後端功能說明，目的是讓 PM 能掌握：

  • 後端要支援哪些「模板系統參數」與「模板組合／擴充」規則
  • 預約查詢頁面的簡訊相關功能，後端要提供哪些能力
  • 後端要留存哪些操作紀錄（Log），供稽核與客服追查
範圍決策提醒（勿走回頭路）：跨門市瀏覽／複製模板功能已於 2026-07-02 定案移除。各門市只能讀取/管理本門市自訂模板與系統內建模板（store_id = NULL），資料完全隔離，不做跨店機制。
本文件不涉及 Schema 型別、SQL、API Request/Response 這類工程實作細節，僅聚焦於業務規則本身。

派號欄位澄清：原型（預約操作模擬.html）曾用「預約時間 → 換算時段起點 → 每 15 分鐘遞增奇數」的公式產生 {{派號}}，這套公式只是原型示意假資料，不是後端真正規則。實際規則：後端已完成派號功能開發——依同一診間/時段內預約建立的先後順序，自動遞增產生奇數序列（1、3、5、7…），由系統自動派發。

模板的兩種來源與可見性

來源可編輯範圍說明
系統內建不可直接改內容全系統共用；門市編輯後存檔會另存一份自訂複本，原始內建不受影響
本門市自訂可編輯／刪除只有建立的門市看得到、能改；其他門市看不到

會員拒收判斷（適用所有發送入口，非 C 頁專屬）

規則說明
會員拒收判斷會員設定拒絕簡訊時，後端要能判斷並提示，前台人員仍可強制送出；若同時有同日排程衝突，兩種警示會一併顯示，仍以人員最終決定為準
這項是全域規則，B 頁（預約操作發送）與 C 頁（預約查詢管理）都適用，不是 C 頁專屬功能。
3

預約查詢 C 頁相關後端功能

預約建立後，查詢/管理簡訊狀態的主要入口，後端要支援的能力

功能說明
查詢待發排程依預約 ID 查詢該筆是否有排程中的簡訊，供前台顯示「排程中」狀態
取消排程發送（簡訊層級）排程中的簡訊可在發送前取消；已發送/已取消/失敗的排程不可再取消。取消的是這筆簡訊，不是預約本身——取消後預約仍維持原狀態，只有簡訊狀態變成「已取消」
查看簡訊詳情已排程/已送達/已取消/發送失敗的預約，點擊狀態即可查看收件人（隱碼）、內容與字數、套用的模板名稱、建立時間與建立人、依狀態而定的時間或原因。即使預約診療時間已過期，只要簡訊狀態是終態（已送達/已取消/發送失敗），詳情仍可唯讀點閱；「排程中」或「未發送」的過期紀錄則不可互動
重新發送已取消或發送失敗的簡訊可重新觸發發送。不是「原文重寄」，而是重新開啟一次完整的發送流程——會重新跑套用優先序（可能帶出不同模板）、重新判斷會員拒收／同日排程衝突情境，人員可在送出前修改內容
立即發送／預約發送送出簡訊時可選「立即發送」或指定未來時間排程發送
同日多預約僅最早一筆可操作同一會員、同一天若有多筆未取消的有效預約，只有時間最早的一筆會出現可互動的簡訊入口／狀態徽章；其餘唯讀鎖定，不可點擊發送或查看詳情。判斷「最早」只看預約本身是否被取消，不受該筆簡訊自己的狀態影響
取消預約時的自動補位若被取消的是同會員同日多筆預約中最早的一筆，且同日仍有其他有效預約，系統會自動導向次早的一筆，詢問人員是否改對這筆發送簡訊確認；人員確認送出後，原本最早那筆才正式標記為「已取消」
會員拒收判斷適用於所有發送入口（B、C 兩頁皆是），非 C 頁專屬，已移到第 2 節。

操作紀錄（Log）

後端要留存哪些紀錄，供稽核與客服追查

簡訊發送 Log（每一次發送，含立即發送與排程發送）

項目說明
對應預約用預約 ID 關聯，不直接存完整手機號碼
收件人（隱碼）僅顯示末四碼
發送內容已代入參數的最終簡訊文字
簡訊則數依字數換算
排程時間空值代表立即發送
狀態排程中／已送達／已取消／發送失敗
相關時間戳記送達時間／取消時間／失敗原因發生時間

用途：客服查詢發送記錄、統計發送量與失敗率、稽核個資使用情形。

模板異動稽核 Log（新增／編輯／刪除）

項目說明
操作者是誰改的
動作新增／編輯／刪除
被改的模板模板 ID／名稱
異動內容改之前/改之後的差異（名稱、內容、啟用狀態）
操作時間時間戳記

用途：日後追查「誰改了這條簡訊模板、什麼時候改的、改了什麼」，避免模板被誤改後找不到人負責。

兩類 Log 建議保留至少 12 個月。
5

驗收標準（PM／UAT 用）

可直接照這份清單驗收

  • 建立自訂模板時使用白名單以外的參數 → 儲存被擋下並有錯誤提示
  • 切換門市帳號登入 → 看不到其他門市的自訂模板，只看得到自己門市 + 系統內建
  • 門市沒有任何自訂模板時開發送視窗 → 自動套用 BU 指定模板
  • 設定門市預設後開發送視窗 → 優先套用門市預設，不受「上次套用」影響
  • 門市預設模板被刪除後開發送視窗 → 不出錯，自動退到下一層規則
  • 預約查詢頁可看到排程中的簡訊，並可成功取消
  • 取消排程中的簡訊後，預約本身狀態不受影響（僅簡訊變為已取消，預約仍為進行中）
  • 已取消/發送失敗的簡訊可重新發送成功；重新發送會重新套用優先序規則與拒收/衝突情境判斷，非原文重寄
  • 同一會員同一天有多筆有效預約時，只有時間最早一筆可操作簡訊；其餘顯示唯讀且無法點擊
  • 取消同會員同日最早一筆的「預約」時，系統自動導向次早一筆詢問是否發送簡訊，確認送出後原預約才轉為已取消
  • 已過期但簡訊狀態為已送達/已取消/發送失敗的預約，仍可唯讀點閱簡訊詳情內容
  • 後台可查到簡訊發送 Log，手機號碼皆為隱碼
  • 後台可查到模板新增/編輯/刪除的稽核紀錄，含操作者與異動內容
  • 派號欄位在簡訊內容中正確顯示為系統自動遞增的奇數序號（非原型的時間公式）
