本次要解決的問題

從哪裡到哪裡

單一固定模板→ 依門市/情境可選多套模板

現況每間門市只能用同一套固定簡訊內容；擴增後每間門市可以擁有自己的自訂模板、設定門市預設，並在兩個發送簡訊的入口（預約操作、預約查詢）用同一套模板選擇器挑選要套用的模板。

範圍決策（已定案，不要走回頭路）：原本規劃過「其他門市共用模板」（可瀏覽/複製別門市自訂的模板），最終決定移除，聚焦在系統內建模板。未來若有更好的模板組合值得推廣，走法是直接擴充系統內建模板清單，不做跨門市瀏覽或複製機制。
這份文件是派案用規格，不是重講原型長怎樣；三個畫面已有可互動原型（模板簡訊設定教學.html／預約操作模擬.html／預約查詢互動.html），資料層以 localStorage 模擬。工程細節完整版見 docs/擴增需求/前端規格書.md。

三個前端畫面範圍

各自負責什麼、對應原型檔案

🛠️ A. 模板管理　CRUD 中樞

對應原型：prototypes/模板簡訊設定教學.html
  • 清單：可搜尋（比對名稱/說明），依「釘選／本門市自訂／系統內建」分組顯示，同一模板不會同時出現在兩組
  • 編輯器：模板名稱（必填）、用途說明、簡訊內容（必填，可點擊插入 {{參數}}）、即時預覽（手機訊息樣式 + 字數/簡訊則數估算）
  • 編輯規則：本門市自訂可直接改存；系統內建編輯後存檔會另存為自訂複本（不覆蓋原內建，需明確提示，不能靜默發生）
  • 門市預設：可設定/取消目前編輯中的模板為門市預設（影響第 3 節套用優先序）；BU 指定模板為唯讀 badge，沒有互動設定按鈕
  • 啟用/停用：關閉後從發送畫面的選擇器消失，管理清單仍看得到、可重新啟用；系統內建模板固定為啟用
  • 刪除：需二次確認；若刪的剛好是門市預設，要同時清掉預設設定
  • 資料保護：編輯到一半離開（切模板／新增／關頁）需有未儲存變更提醒（isDirty()）

🧩 B. 預約操作 - 發送簡訊　發送入口 1

對應原型：prototypes/預約操作模擬.html
  • 模板選擇器互動規則（收合/展開、chips、覆蓋確認）與 C 頁完全共用，詳見第 4 節
  • 套用優先序、模板來源分組邏輯詳見第 3 節
  • B 頁專屬：客戶若設定「不收簡訊」，要有明顯阻擋提示，避免店員忽略誤送；人員仍可強制送出

🔍 C. 預約查詢 - 簡訊管理狀態　發送入口 2 + 事後管理

對應原型：prototypes/預約查詢互動.html
  • 套用模板的規則跟 B 完全一致，詳見第 4 節
  • 簡訊送出時要記錄本次使用的模板名稱（快照，非外鍵）
  • 排程詳情可查閱：依 5 種簡訊狀態顯示對應狀態列與模板名稱，依狀態提供對應操作，詳見第 6 節
  • 要有連到「模板管理」的捷徑，方便店員發現沒有合用模板時直接跳去建立
  • C 頁專屬三條規則（同日多預約僅最早一筆可操作／簡訊取消≠預約取消／取消最早預約後自動補位）獨立列在第 5 節——這三條已實作並驗收完成，不是新增待開發項目

模板來源與套用優先序

模板從哪裡來、發送視窗開啟時自動帶入哪一個

模板的兩種來源（同一份清單裡混合顯示）

來源ID 前綴可編輯範圍說明
系統內建b不可直接改全系統共用的預設模板；編輯後存檔會建立一份自訂複本，原始內建不受影響
本門市自訂c可編輯／刪除該門市自己建立的模板，只有自己看得到、能改

門市 / 使用者層級的狀態（跟模板本身分開存）

狀態範圍說明
釘選清單門市常用模板釘選後排在清單最前面，也會出現在發送畫面的快速套用 chips
個人上次套用門市開啟發送簡訊視窗時，若沒有門市預設，就沿用這筆；只保留單筆最新紀錄
門市預設門市可設定/取消；設定後開啟發送簡訊視窗會優先帶入這一筆
BU 指定模板系統層級門市完全沒有任何自訂模板時的最終 fallback；本階段為前端寫死常數 BU_DESIGNATED_ID，非資料庫欄位、無後台設定介面

套用優先序（開啟發送簡訊視窗時，由上而下判斷，符合就套用、不再往下）

1. 門市預設存在且未刪除/未停用 → 直接套用
2. 門市是否有任何自訂模板？沒有 → 套用「BU 指定模板」
3. 有「上次套用」紀錄且模板還在？是 → 套用上次模板，顯示「已沿用上次選擇」
4. 曾釘選過本門市自訂模板？是 → 套用最近釘選的自訂模板 否 → 套用最新建立的自訂模板
防呆：門市預設或上次套用指到的模板可能已被刪除/停用，這時要自動退到下一層 fallback，不能整個畫面壞掉或跳錯誤訊息。規則 2-4 套用時不顯示特別提示標記，只有規則 3「上次套用」會標示。「上次套用」僅在使用者主動選擇模板或實際送出時寫入，開窗自動帶入不算，否則規則 4「首次套用」分支永遠不會觸發。實作參考：computeAutoApplyId()。

模板選擇器互動規則

B、C 兩個發送入口共用同一套規則，不可各自長出不同行為

收合狀態（預設）

元件說明
目前套用列「目前套用：模板名稱」＋來源標籤（自訂／系統預設）＋（沿用上次時）綠色「已沿用上次選擇」badge
更換按鈕「更換 ▾」，點擊展開清單
釘選快速套用 chips全程可見、不受收合/展開影響；沒有釘選任何模板時整排不顯示

展開狀態（點「更換」後）

元件說明
篩選輸入框就地篩選下方清單（比對模板名稱），非彈出式 dropdown
清單範圍只放「已啟用的本門市自訂模板」與「系統預設（BU 指定模板）」，不顯示「最近使用」與其他系統內建模板；已釘選的模板不重複出現在清單裡
高度限制max-height:200px + 內部捲動，不撐開整個彈窗
收合按鈕「收合 ▴」，可不選直接收回；選定一筆或點 chips 套用後清單自動收回
覆蓋前確認：若使用者已手動編輯過內容框，此時再切換模板（含點擊 chips），需先跳確認對話框：「目前內容已手動修改，套用新模板將覆蓋這些修改，確定要更換嗎？」取消則不套用、內容維持原樣。開窗自動帶入（silent）不觸發此檢查。實作參考：lastAppliedBody + hasUnsavedEdit()。
開合只由「更換／收合」按鈕控制，不使用 focus/blur/Escape/click-outside 的 combobox 狀態機——這是三輪迭代後的定版設計（v1 下拉選單重複顯示、v2 常駐卡片牆佔版面），後續調整請延續目前版本方向，不要走回舊版。
建議抽成共用元件：模板選擇器（收合/展開/篩選/釘選 chips/覆蓋確認）、套用優先序判斷函式、模板資料存取層、參數解析（{{token}} → 實際值），A/B/C 三頁與 B/C 兩個發送入口都會重複用到，建議統一實作，避免各自維護導致規則跑不同步。

預約查詢 C 頁重點規則

已實作並驗收完成，非新增需求——記錄於此供後續維護者查閱

  • 同日多預約僅最早一筆可操作：同一會員同一天有多筆未取消的預約時，只有時間最早的一筆會出現可互動的簡訊入口／狀態徽章，其餘鎖定唯讀（灰階、不可點擊）；判斷「最早」只看預約本身是否被取消，跟該筆簡訊自己的狀態無關。實作參考：generateActionButtons()。
  • 簡訊取消 ≠ 預約取消：「取消此排程」（cancelSms()）只取消這筆簡訊，預約本身狀態不變；跟「取消預約」（cancelAppointment()）是兩個獨立按鈕/流程，不可合併。
  • 取消最早預約時的自動補位：若取消的正是同會員同日多筆預約中「最早」的一筆，且同日還有其他有效預約，會自動改為對次早那筆開發送視窗詢問是否改發簡訊；使用者確認送出後，原本最早那筆才正式標記為「已取消」；若中途取消發送視窗，原預約不受影響。實作參考：showReplacementModal()。
以上三條規則已於本次原型完整實作並驗收，維護／重構時請對照 docs/擴增需求/前端規格書.md 4.3 節，不要因為看起來像邊角案例就簡化或刪除。

已驗收既有邏輯 vs 待工程師注意事項

哪些不要改動、哪些要跟前端工程師一起拍板

✅ 已驗收，維護時不要改壞

  • 模板選擇器 v3 定版設計（收合＋chips＋展開清單），不要走回 v1/v2 舊版
  • C 頁三條規則（同日最早一筆可操作／簡訊取消≠預約取消／自動補位），見第 5 節
  • 系統內建模板編輯＝另存複本，不覆蓋原內建
  • 「上次套用」只在主動選擇/送出時寫入，開窗自動帶入不寫入
  • A 頁編輯保護（isDirty()）與刪除門市預設時的連動清空

🟡 待跟前端工程師拍板

  • 資料串接方式：正式環境要串真正的後端 API 嗎？模板清單／CRUD／門市預設／個人上次套用分別對應哪些端點？
  • 「個人上次套用」要綁裝置還是登入帳號？（若同門市多帳號共用同一台電腦）
  • BU 指定模板未來是否需要開放後台設定（目前是前端寫死常數）
  • 共用元件怎麼落地：抽成前端共用 component/hook，還是由後端統一回傳算好優先序的預設模板？

前端驗收重點

逐條對照 docs/擴增需求/前端規格書.md 六、互動驗收清單

    模板管理頁（A）

  • 新增模板、儲存後立即出現在清單與發送畫面選擇器
  • 停用模板後不出現在發送畫面選擇器，但管理清單仍顯示（灰階樣式）
  • 點擊參數 chip → 插入游標位置（{{參數}}）
  • 右欄即時預覽隨編輯更新
  • 系統內建模板編輯存檔 → 跳出「另存為自訂複本」確認，不會靜默覆蓋
  • 刪除門市預設模板 → 同步清除門市預設設定
  • 編輯到一半切換模板/新增/離開頁面 → 未儲存變更提醒

    • 發送簡訊模板選擇器（B、C 共用）

  • 開窗時預設收合，僅顯示「目前套用：X」＋來源標籤＋更換按鈕
  • 沿用上次選擇時顯示綠色「已沿用上次選擇」badge
  • 有釘選模板時顯示快速套用 chips；無釘選時整排不顯示
  • 點「更換」→ 展開篩選框＋單欄清單；清單不含已釘選項目；套用中列顯示「套用中」標籤
  • 輸入關鍵字 → 清單就地篩選
  • 清單超過高度上限 → 內部捲動，不撐開彈窗
  • 點選清單項目或 chips → 套用後清單自動收回、目前套用列更新
  • 手動編輯過內容後再切換模板 → 跳覆蓋確認；取消則內容不變、不切換
  • 所有 {{參數}} 在內容框中已解析為實際文字（無 token 殘留）
  • 字數即時計算；超過 70 字顯示「N 則」估算
  • 點「管理模板 ↗」→ 跳轉到模板設定頁
  • （B 頁）客戶拒收簡訊時顯示阻擋提示，仍可強制發送
  • （C 頁）排程詳情依狀態顯示對應操作按鈕，簡訊送出記錄使用的模板名稱
  • （C 頁）同一會員同日有多筆有效預約時，只有最早一筆可操作簡訊，其餘鎖定唯讀不可點擊
  • （C 頁）取消排程中的簡訊後，預約本身狀態不受影響（僅簡訊變為已取消）
  • （C 頁）取消同會員同日最早一筆的「預約」時，自動導向次早一筆詢問是否發送簡訊，確認送出後原預約才轉為已取消
