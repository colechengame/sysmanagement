## 一、文件目的與範圍

本文件是給 **PM／需求溝通**用的前端功能版本，目的是讓 PM 能掌握：

1. 三個前端畫面（模板管理／預約操作發送／預約查詢管理）各自的功能範圍
2. 模板套用的核心邏輯——模板從哪裡來、發送視窗開啟時自動帶入哪一個
3. 可以直接照著驗收的標準（UAT）

現況每間門市只能用同一套固定簡訊內容；本次擴增後，每間門市可以擁有自己的自訂模板、設定門市預設，並在兩個發送入口用同一套模板選擇器挑選要套用的模板。

### 範圍決策提醒（勿走回頭路）

跨門市瀏覽／複製模板功能（可瀏覽/複製其他門市自訂的模板）已於 2026-07-02 定案**移除**，聚焦在系統內建模板。各門市只能讀取/管理**本門市自訂模板**與**系統內建模板**，資料完全隔離，不做跨店機制。未來若有更好的模板組合值得推廣，做法是**直接擴充系統內建模板清單**（由系統/BU 端統一新增），不重新討論加回跨門市瀏覽或複製機制。

## 二、模板系統與套用優先序

### 2.1 模板的兩種來源

| 來源 | 可編輯範圍 | 說明 |
|---|---|---|
| 系統內建 | 不可直接改 | 全系統共用的預設模板；編輯後存檔會建立一份自訂複本，原始內建不受影響 |
| 本門市自訂 | 可編輯／刪除 | 該門市自己建立的模板，只有自己看得到、能改 |

### 2.2 模板可用的參數

發送時系統會自動把以下參數換成實際內容，不需人員手動填寫：`{{門市名稱}}`、`{{門市地址}}`、`{{門市電話}}`、`{{預約日期}}`、`{{預約時間}}`、`{{療程}}`、`{{診間}}`、`{{時段}}`、`{{派號}}`、`{{叫號機網址}}`（2026-07-13 新增，門市層級固定值）。

**99－虛擬會員新客規則**：來源為 `99－虛擬會員` 時，B／C 頁一律改用該筆預約的「新客姓名／新客電話」顯示及發送簡訊，不得使用虛擬會員代碼綁定的會員姓名／電話；`HQ0000146` 為範例會員編號。同一天、同一門市可建立多筆不同新客預約，每筆皆可獨立發送。

### 2.3 門市／使用者層級的狀態（跟模板本身分開存）

| 狀態 | 範圍 | 說明 |
|---|---|---|
| 釘選清單 | 門市 | 常用模板釘選後排在管理清單最前面，也會顯示成發送畫面的快速套用 chips |
| 個人上次套用 | 門市 | 開啟發送簡訊視窗時，若沒有門市預設，就沿用這筆；只保留單筆最新紀錄 |
| 門市預設 | 門市 | 可設定/取消；設定後開啟發送簡訊視窗會優先帶入這一筆 |
| BU 指定模板 | 系統層級 | 門市完全沒有任何自訂模板時的最終 fallback；本階段為系統固定指定的一筆系統內建模板，非門市可設定 |

### 2.4 套用優先序（開啟發送簡訊視窗時自動帶入哪一張模板）

依下列 4 條規則**由上而下依序判斷，符合就直接套用、不再往下**：

1. 門市有設「預設模板」且模板還在（未刪除/未停用）？→ 是：**套用門市預設**
2. 門市是否有任何自訂模板？→ 沒有：**套用「BU 指定模板」**
3. 有「上次套用」紀錄且模板還在？→ 是：**套用上次模板**，顯示「已沿用上次選擇」提示
4. 曾釘選過本門市自訂模板？→ 是：**套用最近釘選的自訂模板**；否：**套用最新建立的自訂模板**

**防呆要求**：門市預設或個人上次套用指到的模板可能已被刪除／停用，這時要自動落到下一層 fallback，不能整個畫面壞掉或跳錯誤訊息。「上次套用」僅在使用者**主動選擇模板或實際送出**時記錄，開窗自動帶入不寫入。

## 三、三個畫面功能需求

### A. 模板管理（CRUD 中樞）

- 清單：可搜尋，依「釘選／本門市自訂／系統內建」分組顯示
- 編輯器：模板名稱（必填）、用途說明、簡訊內容（必填，可插入參數）、即時預覽
- 系統內建模板編輯後存檔會**另存為自訂複本**，不覆蓋原內建，需明確提示
- 可設定/取消「門市預設」；刪除模板需二次確認，若刪的剛好是門市預設要同步清空設定
- 啟用/停用：關閉後從發送畫面選擇器消失，管理清單仍看得到、可重新啟用
- 編輯到一半離開需要有未儲存變更提醒
- **建立/更新資訊**（2026-07-28 簡化，取代原「異動稽核 Log」多筆歷史設計）：每張模板卡片直接顯示建立人/建立時間、更新人/更新時間（若有）與啟用狀態；更新直接覆蓋這幾個欄位，不維護逐筆異動歷史——因為每筆模板用 UUID 識別、更新即覆蓋同一列，不需要大量紀錄所有操作

### B. 預約操作 - 發送簡訊（發送入口 1）

- 套用模板規則與 C 頁完全一致（見第四節）
- 客戶若設定「不收簡訊」，要有明顯阻擋提示，避免店員忽略誤送，人員仍可強制送出

### C. 預約查詢 - 簡訊管理狀態（發送入口 2 + 事後管理）

- 套用模板規則與 B 頁完全一致
- **不記錄本次套用的模板名稱**（2026-07-13 定案取消，範圍含前後端）
- 排程詳情可查閱：依 5 種簡訊狀態顯示對應狀態列（不含模板名稱），並依狀態提供對應操作（見第四節）
- 有連到「模板管理」的捷徑

> 以下三條規則**已於本次原型完整實作並驗收**，不是新增待開發項目：

1. **同日多預約僅最早一筆可操作**：一般會員同一天有多筆未取消的預約時，只有時間最早的一筆會出現可互動的簡訊入口／狀態徽章，其餘鎖定唯讀；判斷「最早」只看預約本身是否被取消，跟該筆簡訊自己的狀態無關。99－虛擬會員例外，每筆新客預約皆可操作
2. **簡訊取消 ≠ 預約取消**：「取消此排程」只取消這筆簡訊，預約本身狀態不變；跟「取消預約」是兩個獨立按鈕/流程
3. **取消最早預約時的自動補位**：若取消的正是同會員同日多筆預約中「最早」的一筆，且同日還有其他有效預約，會自動改為對次早那筆開發送視窗詢問是否改發簡訊；使用者確認送出後，原本最早那筆才正式標記為「已取消」

## 四、狀態與互動規則對照

### 4.1 模板選擇器互動規則（B、C 兩個發送入口共用）

發送視窗採**左右並排**版面：左欄是篩選框＋模板清單（只放「已啟用的本門市自訂模板」與「系統預設」，已釘選的不重複出現，套用中/沿用上次選擇以標籤標示），右欄固定顯示簡訊內容，兩者同時可見、不收合，切模板不會讓內容框位置跟著跳動；有釘選模板時另有一排快速套用 chips 橫跨兩欄上方全程可見。

若使用者已手動編輯過內容，此時再切換模板，需先跳確認對話框才覆蓋，避免無聲蓋掉手動修改的內容。

### 4.2 簡訊狀態、操作、Modal 對照（C 頁排程詳情）

| 簡訊狀態 | 可用操作 | 對應 Modal / 提示 |
|---|---|---|
| 未發送 | —（尚未建立排程） | — |
| 排程中 | 取消此排程 | 取消需確認；取消後只改簡訊狀態，預約不受影響 |
| 已送達 | 關閉 | 唯讀查閱，僅能關閉詳情視窗 |
| 已取消 | 重新發送 | 重新發送＝重新走一次套用優先序＋內容確認，非原文重寄 |
| 發送失敗 | 重新發送 | 同上；顯示失敗原因 |

其他跨頁提醒：A 頁編輯到一半離開有未儲存變更提醒；A 頁編輯系統內建模板存檔會跳「另存為自訂複本」確認；A 頁刪除模板需二次確認；C 頁取消最早預約會自動導向次早一筆的發送簡訊視窗（自動補位）。

## 五、驗收標準（PM／UAT 用）

### 模板管理頁

- [ ] 新增模板、儲存後立即出現在清單與發送畫面選擇器
- [ ] 停用模板後不出現在發送畫面選擇器，但管理清單仍顯示
- [ ] 系統內建模板編輯存檔 → 跳出「另存為自訂複本」確認，不會靜默覆蓋
- [ ] 刪除門市預設模板 → 同步清除門市預設設定
- [ ] 編輯到一半切換模板/新增/離開頁面 → 未儲存變更提醒
- [ ] 新增模板 → 卡片「建立」顯示目前操作人與今天日期
- [ ] 編輯已存在的模板並儲存（含切換啟用/停用）→ 卡片「更新」顯示目前操作人與今天日期，覆蓋掉上一次的更新資訊

### 發送簡訊模板選擇器（B、C 共用）

- [ ] 發送視窗左右並排顯示：左欄模板清單、右欄簡訊內容，全程同時可見，不收合
- [ ] 沿用上次選擇時，該模板列/釘選 chip 顯示「已沿用上次選擇」提示
- [ ] 有釘選模板時顯示快速套用 chips；無釘選時整排不顯示
- [ ] 手動編輯過內容後再切換模板 → 跳覆蓋確認；取消則內容不變、不切換
- [ ] （B 頁）客戶拒收簡訊時顯示阻擋提示，仍可強制發送
- [ ] （C 頁）排程詳情依狀態顯示對應操作按鈕（不含模板名稱欄位）
- [ ] （C 頁）一般會員同日多預約僅最早一筆可操作；99－虛擬會員的各筆新客預約皆可獨立操作
- [ ] （B／C 頁）99－虛擬會員顯示新客姓名／電話，並用新客電話發送簡訊
- [ ] （C 頁）取消排程中的簡訊後，預約本身狀態不受影響（僅簡訊變為已取消）
- [ ] （C 頁）取消同會員同日最早一筆的「預約」時，自動導向次早一筆詢問是否發送簡訊，確認送出後原預約才轉為已取消
