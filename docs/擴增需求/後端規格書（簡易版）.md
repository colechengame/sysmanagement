# NPOS 預約簡訊多模板｜後端實作規格（簡易版）

> v1.1　2026-06-30　補入診間／時段／派號三個系統參數與推算邏輯

---

## 一、系統參數白名單

`body` 欄位僅允許以下 token，其他 `{{...}}` 格式儲存時回 400。

| Token | 說明 | 解析來源 |
|---|---|---|
| `{{會員姓名}}` | 會員全名 | `appointments.member_name` |
| `{{門市名稱}}` | 門市名稱 | `stores.name` |
| `{{預約日期}}` | 格式 `MM/DD（星期）` | `appointments.date` |
| `{{預約時間}}` | 格式 `HH:MM` | `appointments.time` |
| `{{療程}}` | 施做療程項目 | `appointments.treatment_name` |
| `{{診間}}` | 診療室（診一、診二 …） | `appointments.room` |
| `{{時段}}` | 早診 / 午診 / 晚診（由時間推算，見第二節） | 後端計算 |
| `{{派號}}` | 預估派號（由時間推算，見第二節） | 後端計算 |
| `{{門市地址}}` | 完整地址 | `stores.address` |
| `{{門市電話}}` | 含區碼，如 `02-XXXX-XXXX` | `stores.phone` |

## 二、時段與派號推算規則

> 派號僅為**預估值**，實際號碼由現場工作人員決定；後端在解析簡訊 token 時依此規則填入。

### 2.1 時段判斷

```
appointment.time（HH:MM）→ 換算成分鐘數 total

total < 13:00（780 分）  → 早診
total < 17:00（1020 分） → 午診
total ≥ 17:00            → 晚診
```

### 2.2 派號公式

各時段起點（分鐘）：

| 時段 | 起點 |
|---|---|
| 早診 | 09:30（570 分） |
| 午診 | 13:00（780 分） |
| 晚診 | 17:00（1020 分） |

```
offset = floor( (total − shiftStart) / 15 )   // 每 15 分鐘一格
派號   = 1 + offset × 2                        // 奇數序列：1、3、5 …
```

範例：

| 預約時間 | 時段 | 派號 |
|---|---|---|
| 09:30 | 早診 | 1 |
| 10:00 | 早診 | 5 |
| 13:00 | 午診 | 1 |
| 17:00 | 晚診 | 1 |
| 17:30 | 晚診 | 5 |
| 18:00 | 晚診 | 9 |
| 19:30 | 晚診 | 21 |

## 三、資料模型（重點欄位）

### `sms_templates`

| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | VARCHAR(36) PK | 系統內建前綴 `builtin_`，自訂前綴 `c_` |
| `store_id` | INT FK | NULL = 全系統共用 |
| `name` | VARCHAR(64) | 同門市範圍唯一 |
| `body` | TEXT | 含 `{{Token}}` 的模板內容 |
| `enabled` | BOOLEAN | false 時不出現在前端下拉 |
| `is_builtin` | BOOLEAN | true 時不可刪除、不可改 body |

### `sms_user_preferences`

| 欄位 | 型別 | 說明 |
|---|---|---|
| `user_id` | INT PK | |
| `pinned_ids` | JSON Array | 釘選模板 ID |
| `recent_ids` | JSON Array | 最近使用（上限 5） |
| `last_used_id` | VARCHAR(36) | 上次套用的模板 ID |

### `sms_store_settings`

| 欄位 | 型別 | 說明 |
|---|---|---|
| `store_id` | INT PK | |
| `sms_enabled` | BOOLEAN | 全域發送開關 |
| `include_tele` | BOOLEAN | 包含電訪推廣附加語 |

### `sms_send_log`

| 欄位 | 型別 | 說明 |
|---|---|---|
| `appointment_id` | INT FK | 用於查手機號碼，不直接儲存完整號碼 |
| `recipient_masked` | VARCHAR(20) | 隱碼：`09xx-ooo-NNNN`（僅末四碼） |
| `content` | TEXT | 已解析的最終簡訊文字 |
| `segments` | INT | 簡訊則數 |
| `scheduled_at` | DATETIME | NULL = 立即發送 |
| `status` | ENUM | `pending` / `sent` / `failed` |

## 四、API 端點速查

| 動作 | Method | 路徑 | 權限 |
|---|---|---|---|
| 取得模板清單 | GET | `/api/sms-templates` | 全員 |
| 新增自訂模板 | POST | `/api/sms-templates` | 門市主管↑ |
| 更新模板 | PUT | `/api/sms-templates/:id` | 門市主管↑（內建模板僅可改 `enabled`） |
| 刪除自訂模板 | DELETE | `/api/sms-templates/:id` | 門市主管↑（內建不可刪） |
| 取得個人偏好 | GET | `/api/user/sms-preferences` | 全員 |
| 更新個人偏好 | PUT | `/api/user/sms-preferences` | 全員 |
| 發送簡訊 | POST | `/api/sms/send` | 全員 |
| 取得門市設定 | GET | `/api/store/settings` | 全員 |
| 更新門市設定 | PUT | `/api/store/settings` | 門市主管↑ |

### POST `/api/sms/send` 重點欄位

```json
{
  "appointment_id": 10042,
  "template_id": "b2",
  "content": "已解析的最終文字（前端人員可能已手動修改）",
  "scheduled_at": null
}
```

- `appointment_id` → 後端自行取手機號碼，前端不傳
- `content` → 長度上限 670 字；超過回 400
- `scheduled_at` 為 null 或省略 → 立即發送

## 五、個資處理規則

| 規則 | 說明 |
|---|---|
| 手機號碼 | 由後端從 `appointment_id` 關聯取得；不接受前端傳入完整號碼 |
| Log 儲存 | `recipient_masked` 僅儲存末四碼（`09xx-ooo-NNNN`） |
| API Response | 不回傳完整手機號碼 |
| 會員拒絕簡訊 | 後端判斷拒絕狀態，回 400 並說明原因；前端仍可顯示警告後強制送出 |
