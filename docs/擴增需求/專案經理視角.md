# NPOS 預約簡訊多模板系統｜專案經理視角

> 版本：v1.0　　撰寫日期：2026-06-26　　狀態：規劃中

> ⚠️ **注意**：本文件為早期規劃版本，部分規則其後已有調整（「最近使用」清單移除、新增「BU 指定模板」fallback、套用優先序加入首次套用分支等）。最新規格請以 `prototypes/簡報.html`（前端）與 `prototypes/後端簡報.html`（後端）為準。

## 一、背景與目標

### 為什麼做這件事？

現行 NPOS 系統發送預約確認簡訊時只有**單一固定格式**，無法因應不同科別（中醫 / 醫美 / 一般）或門市風格的差異化需求。人員若想調整文字，需要走後台工程，效率低且依賴資訊部門。

### 要解決的問題

| 痛點 | 現況 | 目標 |
|---|---|---|
| 簡訊格式固定 | 全系統只有一種格式 | 多模板，可依情境選擇 |
| 人員無法自訂 | 需工程師改程式碼 | 門市主管可在後台新增、編輯 |
| 重複操作低效 | 每次都要重選模板 | 記住上次選擇，一鍵沿用 |
| 個資外露風險 | 簡訊包含完整個資 | 後端隱碼，前端不顯示完整號碼 |

### 成功定義

> 門市人員在預約確認流程中，平均選擇模板的操作步驟從 4 步減為 1 步（沿用上次）；
> 門市主管可在不依賴工程師的前提下，5 分鐘內新增並啟用一個新模板。

## 二、使用者角色

| 角色 | 使用情境 |
|---|---|
| **前台人員** | 建立或查看預約後，選擇模板發送簡訊確認 |
| **門市主管** | 新增 / 編輯適合本門市的簡訊模板；調整全域發送設定 |
| **系統管理員** | 維護系統內建模板；管理跨門市共用設定 |
| **會員（間接）** | 收到簡訊；可在會員資料設定拒絕簡訊 |

## 三、User Stories

### 前台人員

| ID | Story | 驗收條件 |
|---|---|---|
| US-01 | 建立預約後，系統自動開啟簡訊確認視窗，沿用我上次選的模板，我直接按「確認發送」。 | Modal 開啟時自動套用上次 ID；若首次則套用預設模板；顯示「已沿用上次選擇」標籤 |
| US-02 | 今天有不同療程，我需要換一個模板再發送。 | 切換下拉後 textarea 自動更新為新模板已解析文字；Toast 提示切換成功 |
| US-03 | 我想在發送前微調簡訊文字（例如加一句提醒）。 | textarea 可直接編輯；字數即時更新；以修改後內容發送 |
| US-04 | 會員曾設定不接收簡訊，我打開 Modal 時要看到提醒。 | Modal 頂部顯示警示列說明會員偏好；仍可強制發送（由人員判斷） |
| US-05 | 我預約好了之後要晚一點再發簡訊（預約發送）。 | 選擇「預約發送時間」datetime-local；送出後後端排程，到時才發送 |

### 門市主管

| ID | Story | 驗收條件 |
|---|---|---|
| US-06 | 我要新增一個醫美專用的模板。 | 在設定頁新增模板後，立即出現在預約頁下拉清單 |
| US-07 | 我要暫時停用某個模板（節日後活動結束）。 | 停用後該模板不出現在下拉；設定頁仍可看到（opacity 較淡） |
| US-08 | 我想把常用模板釘選在最上方，方便同事快速找到。 | 釘選後在下拉的 chips 區域優先顯示 |
| US-09 | 旺季期間我要關閉全部簡訊發送（節省簡訊費用）。 | 全域開關關閉後，全門市預約均不觸發 SMS Modal |

### 系統管理員

| ID | Story | 驗收條件 |
|---|---|---|
| US-10 | 我要維護系統內建的 3 種模板（提醒類型），確保格式正確。 | 系統內建模板可更新 body / enabled；不可刪除 |
| US-11 | 我要查看簡訊發送記錄，了解發送量與失敗率。 | 後台 Log 顯示：時間、門市、模板、字數、狀態；手機號碼以隱碼顯示 |

## 四、功能範圍（本次 v1.0）

### In Scope ✅

- 預約操作頁簡訊確認 Modal（模板選取、記住上次、直接發送 / 排程發送）
- 簡訊模板設定頁（新增、編輯、啟用/停用、釘選、搜尋）
- 系統內建模板 3 筆（標準預約提醒、醫美療程提醒、中醫門診提醒）
- 個人偏好持久化（釘選、最近使用、上次模板）
- 全域簡訊開關
- 後端 API（模板 CRUD、偏好儲存、簡訊發送、Log 記錄）
- 個資隱碼處理（手機號碼末四碼保留，Log 不儲存完整號碼）

### Out of Scope ❌（列入後續規劃）

- 簡訊發送費用報表
- 多語系模板
- 簡訊回覆解析（會員自助取消預約）
- 跨門市模板繼承
- 個別人員的模板編輯權限（現為門市主管以上）
- A/B 測試功能

## 六、依賴項目

| 依賴 | 負責方 | 說明 |
|---|---|---|
| SMS Gateway 帳號開通 | 採購 / 資訊 | 需確認電信商（如 every8d、mitake）及簡訊費率 |

| 角色權限系統 | 後端 | 需確認「門市主管」角色判斷邏輯 |
| 排程佇列服務 | 基礎設施 | 可用現有 job queue 或新建（如 BullMQ / Sidekiq） |

## 七、風險管理

| 風險 | 機率 | 衝擊 | 對應策略 |
|---|---|---|---|
| SMS Gateway 開通延誤 | 中 | 高 | M3 先 mock Gateway，上線前再換真實串接 |
| 前台人員操作不熟悉 | 中 | 中 | UAT 含操作示範；設定頁提供操作說明文字 |
| 模板設計錯誤導致錯誤簡訊大量發出 | 低 | 高 | 設定頁強制預覽後才可儲存；上線初期限制每小時發送筆數 |
| 個資外洩（手機號碼） | 低 | 極高 | Log 隱碼儲存；API 不傳遞完整號碼；需通過資安 review |
| localStorage 資料遺失（原型轉正式） | 已知 | 低 | 原型至正式系統切換時一次性資料轉移，或讓使用者重新設定偏好 |

## 八、驗收標準（UAT Checklist）

由門市主管與前台人員各自執行：

### 前台人員流程

- [ ] 建立預約 → 儲存 → SMS Modal 自動開啟
- [ ] Modal 顯示「已沿用上次選擇」（第二次以後）
- [ ] 切換模板後 textarea 更新
- [ ] 修改 textarea 內容後發送
- [ ] 選擇「預約發送時間」後送出，Log 顯示 `pending`
- [ ] 會員拒絕簡訊時 Modal 顯示警示

### 門市主管流程

- [ ] 進入設定頁 → 新增模板 → 儲存 → 預約頁下拉立即出現
- [ ] 停用模板 → 預約頁下拉不再出現
- [ ] 全域開關關閉 → 預約頁不再觸發 SMS Modal
- [ ] 釘選模板 → 預約頁 chips 區域顯示

### 個資合規

- [ ] 後台 Log 手機號碼顯示隱碼（`09xx-ooo-NNNN`）
- [ ] 前端 Network Tab 確認 API Request 不含完整手機號碼
