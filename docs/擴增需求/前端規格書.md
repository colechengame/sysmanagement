## 一、範圍與背景

現況每間門市只能用同一套固定簡訊內容；本次擴增後，每間門市可以擁有自己的自訂模板、設定門市預設，並在兩個發送入口用同一套模板選擇器挑選要套用的模板。

涵蓋三個畫面：

| 畫面 | 對應原型 | 角色 |
|---|---|---|
| 模板管理 | `模板簡訊設定教學.html` | CRUD 中樞：建立/編輯/刪除/釘選/停用模板 |
| 預約操作 - 發送簡訊 | `預約操作模擬.html` | 發送入口 1 |
| 預約查詢 - 簡訊管理狀態 | `預約查詢互動.html` | 發送入口 2，同時是事後查閱/管理簡訊狀態的地方 |

> **範圍決策（已定案）**：曾規劃「其他門市共用模板」（可瀏覽/複製其他門市自訂的模板），最終決定**移除**，聚焦在系統內建模板。未來若有更好的模板組合值得推廣，做法是直接擴充系統內建模板清單（由系統/BU 端統一新增），不做跨門市瀏覽或複製機制。

## 二、核心資料模型

### 2.1 模板的兩種來源

| 來源 | ID 前綴 | 可編輯範圍 | 說明 |
|---|---|---|---|
| 系統內建 | `b` | 不可直接改 | 全系統共用的預設模板；編輯後存檔會建立一份自訂複本，原始內建不受影響 |
| 本門市自訂 | `c` | 可編輯／刪除 | 該門市自己建立的模板，只有自己看得到、能改 |

### 2.2 模板欄位

| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | string | 前綴決定來源類別 |
| `name` | string（必填） | 模板名稱 |
| `desc` | string | 用途說明（一句話描述何時使用） |
| `body` | string（必填） | 簡訊內容，含 `{{參數}}` 佔位符 |
| `enabled` | boolean | 停用後不會出現在發送用的模板選擇器，但仍留在管理清單裡；**系統內建模板固定為 `true`**，要調整需先另存自訂複本 |
| `creator` / `created` | string | 僅「本門市自訂」模板才有，建立者與建立時間 |

### 2.3 參數 Token

所有參數在發送入口套用時由系統自動帶入，不需人員手動填寫：

| Token | 說明 |
|---|---|
| `{{會員姓名}}` | 會員全名 |
| `{{門市名稱}}` | 當前門市名稱 |
| `{{門市地址}}` | 完整地址 |
| `{{門市電話}}` | 含區碼 |
| `{{預約日期}}` | 格式：MM/DD（星期） |
| `{{預約時間}}` | 格式：HH:MM |
| `{{療程}}` | 療程項目名稱 |
| `{{診間}}` / `{{時段}}` / `{{派號}}` | 門診情境專用 |

### 2.4 門市／使用者層級狀態（跟模板本身分開存）

| 狀態 | 範圍 | 說明 |
|---|---|---|
| 釘選清單 | 門市 | 常用模板釘選後排在管理清單最前面，也會顯示成發送畫面的快速套用 chips |
| 個人上次套用 | 門市 | 開啟發送簡訊視窗時，若沒有門市預設，就沿用這筆；只保留單筆最新紀錄，不會顯示成一份歷史清單供選擇 |
| 門市預設 | 門市 | 可設定/取消；設定後開啟發送簡訊視窗會優先帶入這一筆 |
| BU 指定模板 | 系統層級（非門市可設定） | 門市完全沒有任何自訂模板時的最終 fallback；本階段為前端寫死常數 `BU_DESIGNATED_ID`（目前固定指向 `b1`），不是資料庫欄位、也沒有後台設定介面 |

## 三、套用優先序邏輯

開啟發送簡訊視窗時，依下列 4 條規則**由上而下依序判斷，符合就直接套用、不再往下**：

1. 門市有設「預設模板」且模板還在（未刪除/未停用）？→ 是：**套用門市預設**
2. 門市是否有任何自訂模板？→ 沒有：**套用「BU 指定模板」**
3. 有「上次套用」紀錄且模板還在？→ 是：**套用上次模板**，顯示「已沿用上次選擇」提示（**4 條規則中只有這一步會顯示提示標記**）
4. 曾釘選過本門市自訂模板？→ 是：**套用最近釘選的自訂模板**；否：**套用最新建立的自訂模板**

完整 activity diagram 見 `prototypes/套用優先序.puml`（可貼到 PlantUML 線上編輯器或本機渲染查看）。

**防呆**：門市預設或個人上次套用指到的模板可能已被刪除／停用，這時要自動落到下一層 fallback，不能整個畫面壞掉或跳錯誤訊息。

**「上次套用」寫入時機**：僅在使用者**主動選擇模板或實際送出**時記錄，開窗自動帶入（silent）不寫入——否則開過一次視窗就會產生紀錄，規則 4「首次套用」分支永遠不會觸發。

實作參考：`computeAutoApplyId()`（`預約操作模擬.html` / `預約查詢互動.html` 對稱同名函式）。

## 四、三個畫面規格

### 4.1 模板管理（`模板簡訊設定教學.html`）

- 清單：可搜尋（比對名稱/說明），依「釘選／本門市自訂／系統內建」分組顯示，同一模板不會同時出現在兩組
- 編輯器：**模板名稱**（必填）、**用途說明**、**簡訊內容**（必填，可點擊插入 `{{參數}}`）、即時預覽（手機訊息樣式 + 字數/簡訊則數估算）
- 編輯規則：本門市自訂可直接改存；系統內建編輯後存檔會**另存為自訂複本**（不覆蓋原內建，需明確提示，不能靜默發生）
- 門市預設：可設定/取消目前編輯中的模板為門市預設，會影響第三節的套用優先序
- BU 指定模板：唯讀 badge，標示哪一筆是「BU 指定模板」，沒有互動設定按鈕
- 啟用/停用：關閉後這個模板從發送畫面的選擇器消失（釘選 chips 與自動套用也會一併跳過），但管理清單裡還看得到、還能重新啟用
- 刪除：需要二次確認；如果刪的剛好是門市預設，要同時清掉預設設定
- 資料保護：編輯到一半離開（切模板／新增／關頁）需要有未儲存變更的提醒（`isDirty()`）

### 4.2 發送簡訊模板選擇器（B、C 兩個發送入口共用同一套規則）

這是本次規格的核心互動，B（`預約操作模擬.html`）與 C（`預約查詢互動.html`）**規則完全一致**，不可各自長出不同行為。

#### 4.2.1 設計原則

多數情況店員開窗後不需要換模板（已依第三節優先序自動帶入），因此選擇器**預設收合**，只在店員主動要換模板時才展開完整清單——把彈窗空間留給簡訊內容本身。

> 這是三輪迭代後的定版設計：v1「下拉選單＋獨立釘選 chips」同時顯示同一批模板（重複、無預覽、無覆蓋防呆）→ v2「常駐卡片牆」（佔空間、多了要捲、掃視動線差）→ **v3 目前版本**：預設收合＋chips＋展開清單。後續若要調整，請延續 v3 的方向，不要走回 v1/v2。

#### 4.2.2 收合狀態（預設）

| 元件 | 說明 |
|---|---|
| 目前套用列 | 「目前套用：**模板名稱**」＋來源標籤（`自訂` 或 `系統預設`，同 `tagFor()` 判斷邏輯）＋（沿用上次時）綠色「已沿用上次選擇」badge |
| 更換按鈕 | 「更換 ▾」，點擊展開清單 |
| 釘選快速套用 chips | 一排 `★ 模板名稱` chips，**全程可見、不受收合/展開狀態影響**；一鍵套用不必展開清單；沒有釘選任何模板時整排不顯示（不佔版面） |

#### 4.2.3 展開狀態（點「更換」後）

| 元件 | 說明 |
|---|---|
| 篩選輸入框 | 就地篩選下方清單（比對模板名稱），非彈出式 dropdown |
| 選項清單 | 整寬單欄列，每列顯示：模板名稱、來源標籤（`自訂`/`系統預設`）、套用中時額外顯示藍色「套用中」標籤、一行內容預覽（`resolved(t.body)`，CSS `text-overflow:ellipsis` 截斷） |
| 清單範圍 | **只放「已啟用的本門市自訂模板」與「系統預設（BU 指定模板）」**，不顯示「最近使用」與其他系統內建模板；**已釘選的模板不重複出現在清單裡**（已經常駐顯示在收合狀態的 chips，兩處互補、不重複） |
| 高度限制 | `max-height:200px` + `overflow-y:auto`，清單過長時內部捲動，不撐開整個彈窗 |
| 收合按鈕 | 「收合 ▴」，可不選直接收回 |

選定清單中一筆或點擊 chips 套用後，**清單自動收回**（回到收合狀態）。開合只由「更換／收合」按鈕控制，**不使用** focus/blur/Escape/click-outside 的 combobox 狀態機。

#### 4.2.4 資料保護（覆蓋前確認）

若使用者已**手動編輯過**簡訊內容框，此時再切換模板（含點擊釘選 chips），需先跳確認對話框：

> 「目前內容已手動修改，套用新模板將覆蓋這些修改，確定要更換嗎？」

取消則不套用、內容維持原樣。**開窗自動帶入（silent）不觸發此檢查**（此時內容框還是空的）。

實作參考：`lastAppliedBody`（記錄最後一次套用的解析後內容）+ `hasUnsavedEdit()`。

#### 4.2.5 套用邏輯

1. 套用＝將 `body` 依第三節解析後的實際文字，寫入簡訊內容框（覆蓋現有內容，需先過 4.2.4 的確認）
2. 「個人上次套用」只在使用者**主動選擇模板或實際送出**時記錄（見第三節）
3. B 頁（預約操作）額外規則：客戶若設定「不收簡訊」，需有明顯阻擋提示，避免店員忽略誤送
4. C 頁（預約查詢）額外規則：簡訊送出時要記錄本次**使用的模板名稱**（快照，非外鍵），供事後查閱

### 4.3 預約查詢 - 簡訊管理狀態（`預約查詢互動.html` 專屬部分）

- 套用模板規則同 4.2（完全一致）
- 排程詳情可查閱：依 5 種簡訊狀態（未發送／排程中／已送達／已取消／發送失敗）顯示對應顏色的狀態列，並顯示套用的模板名稱
- 詳情畫面依狀態提供對應操作：排程中可「取消此排程」；已取消/發送失敗可「重新發送」；已送達只能「關閉」
- 要有連到「模板管理」的捷徑，方便店員發現目前沒有合用的模板時直接跳去建立

## 五、建議抽成共用邏輯的部分

B、C 兩個畫面重複用到的東西，正式實作時不建議各自複製一份：

- **模板選擇器元件**：收合狀態＋展開清單＋篩選＋釘選 chips＋覆蓋確認，B、C 目前規則完全一致，建議抽成共用元件
- **套用優先序判斷**（第三節，含 `BU_DESIGNATED_ID` 常數）：同一段邏輯，建議抽成共用函式
- **模板資料存取層**：模板清單、CRUD、pins/last/default 狀態的讀寫，A/B/C 三頁都要用到，建議統一由同一層處理
- **參數解析**（`{{token}}` → 實際值）：A 的即時預覽跟 B/C 的套用邏輯都需要，規則要一致

## 六、互動驗收清單

### 模板管理頁
- [ ] 新增模板、儲存後立即出現在清單與發送畫面選擇器
- [ ] 停用模板後不出現在發送畫面選擇器（chips 與展開清單皆排除），但管理清單仍顯示（`.t-card.off` 灰階樣式）
- [ ] 點擊參數 chip → 插入游標位置（`{{參數}}`）
- [ ] 右欄即時預覽隨編輯更新
- [ ] 系統內建模板編輯存檔 → 跳出「另存為自訂複本」確認，不會靜默覆蓋原內建
- [ ] 刪除門市預設模板 → 同步清除門市預設設定
- [ ] 編輯到一半切換模板/新增/離開頁面 → 未儲存變更提醒

### 發送簡訊模板選擇器（B、C 共用）
- [ ] 開窗時預設收合，僅顯示「目前套用：X」＋來源標籤＋更換按鈕
- [ ] 沿用上次選擇時顯示綠色「已沿用上次選擇」badge
- [ ] 有釘選模板時顯示快速套用 chips；無釘選時整排不顯示
- [ ] 點「更換」→ 展開篩選框＋單欄清單；清單不含已釘選項目；套用中列顯示「套用中」標籤
- [ ] 輸入關鍵字 → 清單就地篩選
- [ ] 清單超過高度上限 → 內部捲動，不撐開彈窗
- [ ] 點選清單項目或 chips → 套用後清單自動收回、目前套用列更新
- [ ] 手動編輯過內容後再切換模板 → 跳覆蓋確認；取消則內容不變、不切換
- [ ] 所有 `{{參數}}` 在內容框中已解析為實際文字（無 token 殘留）
- [ ] 字數即時計算；超過 70 字顯示「N 則」估算
- [ ] 點「管理模板 ↗」→ 跳轉到模板設定頁（在 index 框架內同步左側選單）
- [ ] （B 頁）客戶拒收簡訊時顯示阻擋提示，仍可強制發送
- [ ] （C 頁）排程詳情依狀態顯示對應操作按鈕，簡訊送出記錄使用的模板名稱

## 七、邊界條件

| 情境 | 處理方式 |
|---|---|
| `localStorage` 被停用（沙箱） | `try/catch` 退回記憶體物件，功能正常但重整後歸零 |
| 門市預設或上次套用指向的模板已被刪除/停用 | 自動落到下一層 fallback（第三節），不報錯 |
| 展開清單搜尋後結果為 0 | 顯示「無符合的模板」，不殘留分組標題 |
| 簡訊內容超過 70 字 | 顯示則數估算（`ceil(len/67)` 則），允許送出 |
| API / 後端串接失敗（正式環境） | Toast 顯示錯誤訊息；Modal 不自動關閉 |
