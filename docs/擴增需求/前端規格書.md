## 一、範圍與背景

現況每間門市只能用同一套固定簡訊內容；本次擴增後，每間門市可以擁有自己的自訂模板、設定門市預設，並在兩個發送入口用同一套模板選擇器挑選要套用的模板。

涵蓋三個畫面：

| 畫面 | 對應原型 | 角色 |
|---|---|---|
| 模板管理 | `模板簡訊設定教學.html` | CRUD 中樞：建立/編輯/刪除/釘選/停用模板 |
| 預約操作 - 發送簡訊 | `預約操作模擬.html` | 發送入口 1 |
| 預約查詢 - 簡訊管理狀態 | `預約查詢互動.html` | 發送入口 2，同時是事後查閱/管理簡訊狀態的地方 |

> **範圍決策（已定案）**：曾規劃「其他門市共用模板」（可瀏覽/複製其他門市自訂的模板），最終決定**移除**，聚焦在系統內建模板。未來若有更好的模板組合值得推廣，做法是直接擴充系統內建模板清單（由系統/BU 端統一新增），不做跨門市瀏覽或複製機制。

## 二、核心資料模型

### 2.1 模板的兩種來源

| 來源 | ID 前綴 | 可編輯範圍 | 說明 |
|---|---|---|---|
| 系統內建 | `b` | 不可直接改 | 全系統共用的預設模板；編輯後存檔會建立一份自訂複本，原始內建不受影響 |
| 本門市自訂 | `c` | 可編輯／刪除 | 該門市自己建立的模板，只有自己看得到、能改 |

### 2.2 模板欄位

| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | string | 前綴決定來源類別 |
| `name` | string（必填） | 模板名稱 |
| `desc` | string | 用途說明（一句話描述何時使用） |
| `body` | string（必填） | 簡訊內容，含 `{{參數}}` 佔位符 |
| `enabled` | boolean | 停用後不會出現在發送用的模板選擇器，但仍留在管理清單裡；**系統內建模板固定為 `true`**，要調整需先另存自訂複本 |
| `creator` / `created` | string | 僅「本門市自訂」模板才有，建立者與建立時間 |

### 2.3 參數 Token

所有參數在發送入口套用時由系統自動帶入，不需人員手動填寫：

| Token | 說明 |
|---|---|
| `{{門市名稱}}` | 當前門市名稱 |
| `{{門市地址}}` | 完整地址 |
| `{{門市電話}}` | 含區碼 |
| `{{預約日期}}` | 格式：MM/DD（星期） |
| `{{預約時間}}` | 格式：HH:MM |
| `{{療程}}` | 療程項目名稱 |
| `{{診間}}` / `{{時段}}` / `{{派號}}` | 門診情境專用 |
| `{{叫號機網址}}` | 門診叫號/報到查詢用短網址，門市層級固定值（2026-07-13 新增，隨「中醫－門診提醒自動報到」系統內建模板一併加入） |

### 2.4 門市／使用者層級狀態（跟模板本身分開存）

| 狀態 | 範圍 | 說明 |
|---|---|---|
| 釘選清單 | 門市 | 常用模板釘選後排在管理清單最前面，也會顯示成發送畫面的快速套用 chips |
| 個人上次套用 | 門市 | 開啟發送簡訊視窗時，若沒有門市預設，就沿用這筆；只保留單筆最新紀錄，不會顯示成一份歷史清單供選擇 |
| 門市預設 | 門市 | 可設定/取消；設定後開啟發送簡訊視窗會優先帶入這一筆 |
| BU 指定模板 | 系統層級（非門市可設定） | 門市完全沒有任何自訂模板時的最終 fallback；依門市自己的科別（見 2.4.1）決定指向哪一筆系統內建模板，不是資料庫欄位、也沒有後台設定介面 |

#### 2.4.1 門市科別（BU）與系統內建模板範圍（2026-07-27 新增）

- **一間門市只會是單一科別**（西醫或中醫擇一，不會混）；本階段前端用常數 `STORE_BU` 代表本門市科別（示範門市固定為 `BU1`／西醫），正式後端應改為門市資料的實際欄位。
- 系統內建模板（`builtin`）本身橫跨全系統多個科別（目前 `b1`/`b2`＝西醫、`b3`/`b4`＝中醫），但**任一門市只能看到、選到跟自己科別相同的系統內建模板**：模板管理頁「系統內建」分組、發送簡訊視窗的「系統預設」選項，都要先用 `t.bu===STORE_BU` 篩過，不相干科別的系統模板不會出現在該門市的任何清單裡。
- `BU_DESIGNATED_ID`（第三節套用優先序規則 2 用到的 fallback）不是全系統寫死同一個 ID，而是「依本門市科別去查對應科別的指定模板」（例如 `{BU1:"b1", BU2:"b3"}` 這種對照表），西醫門市 fallback 到 `b1`、中醫門市 fallback 到 `b3`。
- **門市自訂模板不需要額外的科別欄位／篩選**：因為門市本身就是單一科別，該門市建立的自訂模板天生就只會被自己看到（`custom` 清單本來就已經是門市自己的資料），不會有跨科別自訂模板混進來的問題，只有「系統內建」這種橫跨全系統的資料才需要照科別篩。
- 實作參考：`STORE_BU` / `BU_DESIGNATED_MAP` / `builtinInStore`（三個原型檔同名同邏輯，KEEP IN SYNC 註解互相對照）。

### 2.5 99－虛擬會員新客顯示與發送

- 新客來源判斷值為 `99－虛擬會員`，`HQ0000146` 為範例會員編號。
- B 預約操作與 C 預約查詢都必須顯示該筆預約的「新客姓名／新客電話」，不可顯示虛擬會員代碼綁定的會員姓名／電話。
- 發送簡訊時，以該筆「新客電話」作為實際收件號碼；簡訊詳情的收件人也顯示新客姓名與新客電話。
- 同一虛擬會員代碼可在同一天、同一門市建立多筆不同新客預約；C 頁不可只依虛擬會員代碼將不同預約判定為同一會員衝突，也不可套用「同日僅最早一筆可操作」的鎖定。

## 三、套用優先序邏輯

開啟發送簡訊視窗時，依下列 4 條規則**由上而下依序判斷，符合就直接套用、不再往下**：

1. 門市有設「預設模板」且模板還在（未刪除/未停用）？→ 是：**套用門市預設**
2. 門市是否有任何自訂模板？→ 沒有：**套用「BU 指定模板」**
3. 有「上次套用」紀錄且模板還在？→ 是：**套用上次模板**，顯示「已沿用上次選擇」提示（**4 條規則中只有這一步會顯示提示標記**）
4. 曾釘選過本門市自訂模板？→ 是：**套用最近釘選的自訂模板**；否：**套用最新建立的自訂模板**

完整 activity diagram 見 `prototypes/套用優先序.puml`（可貼到 PlantUML 線上編輯器或本機渲染查看）。

**防呆**：門市預設或個人上次套用指到的模板可能已被刪除／停用，這時要自動落到下一層 fallback，不能整個畫面壞掉或跳錯誤訊息。

**「上次套用」寫入時機**：僅在使用者**主動選擇模板或實際送出**時記錄，開窗自動帶入（silent）不寫入——否則開過一次視窗就會產生紀錄，規則 4「首次套用」分支永遠不會觸發。

實作參考：`computeAutoApplyId()`（`預約操作模擬.html` / `預約查詢互動.html` 對稱同名函式）。

## 四、三個畫面規格

### 4.1 模板管理（`模板簡訊設定教學.html`）

- 清單：可搜尋（比對名稱/說明），依「釘選／本門市自訂／系統內建」分組顯示，同一模板不會同時出現在兩組
- 編輯器：**模板名稱**（必填）、**用途說明**、**簡訊內容**（必填，可點擊插入 `{{參數}}`）、即時預覽（手機訊息樣式 + 字數/簡訊則數估算）
- 編輯規則：本門市自訂可直接改存；系統內建編輯後存檔會**另存為自訂複本**（不覆蓋原內建，需明確提示，不能靜默發生）
- 門市預設：可設定/取消目前編輯中的模板為門市預設，會影響第三節的套用優先序
- BU 指定模板：唯讀 badge，標示哪一筆是「BU 指定模板」，沒有互動設定按鈕
- 啟用/停用：關閉後這個模板從發送畫面的選擇器消失（釘選 chips 與自動套用也會一併跳過），但管理清單裡還看得到、還能重新啟用
- 刪除：需要二次確認；如果刪的剛好是門市預設，要同時清掉預設設定
- 資料保護：編輯到一半離開（切模板／新增／關頁）需要有未儲存變更的提醒（`isDirty()`）
- **模板異動稽核 Log 查看畫面**：頁首「📋 異動紀錄」按鈕開啟全部模板的異動清單（可依模板／動作篩選），每張模板卡片另有「🕒」小圖示，開同一個清單並預先篩好該模板；清單依操作時間新到舊排序，每列可展開查看該筆異動的名稱/內容/啟用狀態 before→after（新增/刪除只顯示單邊，沒有 before/after 對照）；模板被刪除後，篩選清單仍保留該模板（標示「已刪除」），對應的異動紀錄不會跟著消失

### 4.2 發送簡訊模板選擇器（B、C 兩個發送入口共用同一套規則）

這是本次規格的核心互動，B（`預約操作模擬.html`）與 C（`預約查詢互動.html`）**規則完全一致**，不可各自長出不同行為。

#### 4.2.1 設計原則

> 迭代歷史：v1「下拉選單＋獨立釘選 chips」同時顯示同一批模板（重複、無預覽、無覆蓋防呆）→ v2「常駐卡片牆」（佔空間、多了要捲、掃視動線差）→ v3「預設收合＋chips＋點擊展開清單」（問題：展開清單會把下面的簡訊內容往下推，使用者在「選模板」與「看套用後的內容」之間要反覆上下移動視線，PM 實測回報體驗不好）→ v4「左右並排、清單全程可見」（2026-07-21 定案；問題：左欄only 216px 寬、預覽又用 `line-clamp:2` 截斷，模板內容還是看不全）→ v5（2026-07-21 同日再修）：左欄加寬＋預覽不截斷，模板全文直接可讀→ **v6 目前版本（2026-07-27 再修）：清單卡片拿掉預覽全文，只留模板名稱＋來源標籤／狀態標籤**（原因：門市模板一多，加上釘選 chips，每列兩行預覽讓整個清單看起來很擠；模板全文本來就會在選取後立刻顯示在右欄「簡訊內容」框，清單不需要重複顯示一次）。後續若要調整，請延續 v6（左右並排、清單精簡、內容在右欄即時可見）的方向，不要走回 v1/v2/v3 的收合互動，也不要在清單卡片裡重新加回預覽文字（不論截斷與否）。

彈窗（B/C 兩處的簡訊發送 modal）加寬至 `760px`（v4 是 `680px`，原始 v1-v3 是 `520px`），左欄清單寬度加到 `280px`（v4 是 `216px`），模板清單固定放在左欄、簡訊內容固定放在右欄，兩者同時可見；切換模板時只需要視線左右移動比對，不需要展開/收合造成的上下位移。

#### 4.2.2 版面配置

| 區塊 | 說明 |
|---|---|
| 標題列 | 「💬 套用簡訊模板」＋右側「管理模板 ↗」連結（維持原位置，不放進左右欄） |
| 釘選快速套用 chips | 一排 `★ 模板名稱` chips，橫跨左右欄上方、**全程可見**；一鍵套用；沒有釘選任何模板時整排不顯示（不佔版面）；若目前套用的正是某個釘選模板且屬於「沿用上次選擇」，chip 上會多一個小型綠色「沿用上次」badge |
| 左欄：篩選輸入框 | 就地篩選下方清單（比對模板名稱） |
| 左欄：選項清單 | 整寬單欄列，每列只顯示：模板名稱、來源標籤（`自訂`/`系統預設`）、套用中時額外顯示藍色「套用中」標籤（沿用上次選擇時再加綠色「已沿用上次選擇」標籤）；**不顯示內容預覽**（v6 拿掉，見 4.2.1 迭代歷史）——模板全文只在右欄「簡訊內容」框呈現，選取後立即可見，清單不重複顯示一次 |
| 左欄：清單範圍 | **只放「已啟用的本門市自訂模板」與「系統預設（BU 指定模板）」**，不顯示「最近使用」與其他系統內建模板；**已釘選的模板不重複出現在清單裡**（已經常駐顯示在 chips，兩處互補、不重複） |
| 左欄：高度限制 | 固定 `height:320px`（**非** `max-height`）+ `overflow-y:auto`：無論篩選後剩幾筆結果，清單區塊的外觀高度都不隨結果數量縮放，避免使用者輸入篩選關鍵字時清單忽長忽短；v6 拿掉預覽後每列高度固定為單行，捲動時機比 v5 少很多，但高度限制規則本身維持不變 |
| 右欄 | 簡訊內容 label、收件人/提示文字、`<textarea>`、字數/則數統計——跟左欄清單同時可見，選了哪個模板、內容立刻在旁邊更新，不需要往下滑或收合清單才看得到 |

點清單中一筆或點擊 chips 套用後**清單維持展開、不會收合**（因為本來就沒有收合狀態）；小螢幕（`max-width:700px`）時左右欄改為上下堆疊，此時才會有「先看到清單、往下滑到內容」的順序，但這是版面寬度不足的退階顯示，不是互動狀態切換，不會有位移感。

#### 4.2.4 資料保護（覆蓋前確認）

若使用者已**手動編輯過**簡訊內容框，此時再切換模板（含點擊釘選 chips），需先跳確認對話框：

> 「目前內容已手動修改，套用新模板將覆蓋這些修改，確定要更換嗎？」

取消則不套用、內容維持原樣。**開窗自動帶入（silent）不觸發此檢查**（此時內容框還是空的）。

實作參考：`lastAppliedBody`（記錄最後一次套用的解析後內容）+ `hasUnsavedEdit()`。

#### 4.2.5 套用邏輯

1. 套用＝將 `body` 依第三節解析後的實際文字，寫入簡訊內容框（覆蓋現有內容，需先過 4.2.4 的確認）
2. 「個人上次套用」只在使用者**主動選擇模板或實際送出**時記錄（見第三節）
3. B 頁（預約操作）額外規則：客戶若設定「不收簡訊」，需有明顯阻擋提示，避免店員忽略誤送
4. **不記錄本次套用的模板名稱**（2026-07-13 定案取消，範圍含前後端）：簡訊詳情不顯示「使用模板」欄位，`sms_send_log` 也不存 `template_id`

### 4.3 預約查詢 - 簡訊管理狀態（`預約查詢互動.html` 專屬部分）

- 套用模板規則同 4.2（完全一致）
- 排程詳情可查閱：依 5 種簡訊狀態（未發送／排程中／已送達／已取消／發送失敗）顯示對應顏色的狀態列（不含模板名稱）
- 詳情畫面依狀態提供對應操作：排程中可「取消此排程」；已取消/發送失敗可「重新發送」；已送達只能「關閉」
- 要有連到「模板管理」的捷徑，方便店員發現目前沒有合用的模板時直接跳去建立

> 以下三條規則**已於本次原型完整實作並驗收**，不是待開發項目，記錄於此供未來維護者查閱（避免非原開發人員接手時誤判、改壞既有邏輯）：

**同日多預約僅最早一筆可操作**：一般會員同一天若有多筆**未取消**的有效預約，只有時間最早的一筆會出現可互動的簡訊入口／狀態徽章；其餘同日預約的簡訊入口為唯讀鎖定狀態（灰階、不可點擊），不能發送也不能查看詳情。判斷「最早」只看預約本身是否被取消，不受該筆簡訊自己的狀態（例如簡訊已被取消）影響。來源為 `99－虛擬會員` 時例外，每筆皆可獨立操作。實作參考：`generateActionButtons()` 內的同日最早預約判斷。

**簡訊取消 ≠ 預約取消**：「取消此排程」只是取消這筆簡訊（`cancelSms()`），預約本身狀態不變、仍維持進行中；「取消預約」是另一個獨立按鈕/流程（`cancelAppointment()`），兩者不可合併成同一個動作。

**取消最早預約時的自動補位**：若使用者要取消的是同會員同日多筆預約中「最早」的一筆，且同日還有其他有效預約，畫面會自動改為對**次早**的一筆開啟發送簡訊視窗，詢問是否要改對這筆發送確認；使用者確認送出後，原本最早那筆才正式標記為「已取消」，若中途取消發送視窗則原預約不受影響。實作參考：`showReplacementModal()`。

## 五、建議抽成共用邏輯的部分

B、C 兩個畫面重複用到的東西，正式實作時不建議各自複製一份：

- **模板選擇器元件**：收合狀態＋展開清單＋篩選＋釘選 chips＋覆蓋確認，B、C 目前規則完全一致，建議抽成共用元件
- **套用優先序判斷**（第三節，含 `BU_DESIGNATED_ID` 常數）：同一段邏輯，建議抽成共用函式
- **模板資料存取層**：模板清單、CRUD、pins/last/default 狀態的讀寫，A/B/C 三頁都要用到，建議統一由同一層處理
- **參數解析**（`{{token}}` → 實際值）：A 的即時預覽跟 B/C 的套用邏輯都需要，規則要一致

## 七、邊界條件

| 情境 | 處理方式 |
|---|---|
| `localStorage` 被停用（沙箱） | `try/catch` 退回記憶體物件，功能正常但重整後歸零 |
| 門市預設或上次套用指向的模板已被刪除/停用 | 自動落到下一層 fallback（第三節），不報錯 |
| 展開清單搜尋後結果為 0 | 顯示「無符合的模板」，不殘留分組標題 |
| 簡訊內容超過 70 字 | 顯示則數估算（`ceil(len/67)` 則），允許送出 |
| API / 後端串接失敗（正式環境） | Toast 顯示錯誤訊息；Modal 不自動關閉 |
