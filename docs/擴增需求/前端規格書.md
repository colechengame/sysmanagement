# NPOS 預約簡訊多模板系統｜前端規格書

> 版本：v1.0　　撰寫日期：2026-06-26　　狀態：待實作

---

## 一、功能範圍

在現有 NPOS 預約排程系統中，新增「多模板簡訊確認」功能，涵蓋兩個主要頁面：

| 頁面 | 路由（暫定） | 說明 |
|---|---|---|
| 預約操作頁 | `/appointment` | 床位排程表；點擊預約後觸發簡訊確認彈窗 |
| 簡訊模板設定頁 | `/sms-template-settings` | 建立、編輯、啟用/停用全系統共用模板 |

### 2.2 預約操作頁

#### 2.2.1 工具列

| 元件 | 說明 |
|---|---|
| 日期選擇器 | 切換顯示日期 |
| 門市下拉 | 切換門市（影響預約資料來源） |
| 床位篩選 | 顯示全部 / 特定床位 |
| 「＋ 新增預約」按鈕 | 快速開啟建立預約彈窗（直接帶入當日） |

#### 2.2.2 床位排程表

- 列：8 床（床1–床8）
- 欄：時段（09:00–17:00，每 30 或 60 分鐘一格，視門市設定）
- 點擊**空格** → 開啟「建立預約」Modal
- 點擊**已有預約格** → 直接開啟「發出簡訊內容」Modal（因預約已存在）
- 格內顯示：會員姓名、療程名稱、簡訊偏好標記

**顏色語意**

| 色塊 | 用途 |
|---|---|
| `#dbe7fb`（藍） | 一般預約 |
| `#d6efef`（青） | 中醫門診 |
| `#f6dcdc`（紅） | 待確認 / 衝突 |
| `#f7deea`（粉） | 醫美療程 |
| 空白 | 可預約 |

#### 2.2.3 建立預約 Modal

欄位（必填 *）：

| 欄位 | 型別 | 說明 |
|---|---|---|
| 會員姓名 * | text | 可搜尋會員（後端 API 提供建議清單） |
| 簡訊偏好 | checkbox | 「拒絕接收預約簡訊」；勾選後 SMS Modal 顯示警示 |
| 床位 * | select | 預填點擊所在床位 |
| 療程類別 * | select | 中醫 / 醫美 / 一般 |
| 療程項目 * | select | 依類別動態載入 |
| 預約日期 * | date | 預填今日 |
| 預約時段 * | select | 預填點擊所在時段 |
| 備註 | textarea | |

存檔成功後，依是否需發送簡訊跳轉行為：

```
存檔
 ├─ 會員「拒絕簡訊」→ Toast 提示「已建立預約，不發送簡訊」→ 關閉
 └─ 否 → 開啟「發出簡訊內容」Modal
```

#### 2.2.4 發出簡訊內容 Modal

```
┌─────────────────────────────────────────┐
│  標題：發出簡訊內容                ✕   │
├─────────────────────────────────────────┤
│  [警示列] 若會員拒絕簡訊則顯示          │
│                                         │
│  ─ 模板選取列 ──────────────────────── │
│  下拉：選擇模板                         │
│  目前套用：標準預約提醒  [已沿用上次]   │
│  [釘選模板快捷 chips]                   │
│  管理模板 ↗                            │
│                                         │
│  簡訊內容（可編輯 textarea）            │
│  套用後已帶入預約資料，可直接編輯後發送│
│                                         │
│  [字數 47 字  ·  1 則]                 │
│                                         │
│  預約發送時間 [datetime-local]          │
├─────────────────────────────────────────┤
│           [取消]      [確認發送]        │
└─────────────────────────────────────────┘
```

**模板選取邏輯**

1. Modal 開啟時，讀取上次使用的模板 ID（`lastId`）。
2. 若 `lastId` 存在且對應模板仍有效 → 自動套用，顯示「已沿用上次選擇」綠色標籤。
3. 若不存在 → 套用預設模板（第一筆已啟用模板）。
4. 套用時，將 `{{參數}}` 以當下預約資料解析為實際文字後寫入 textarea。
5. 人員可在 textarea 內自由修改最終發送內容。
6. 切換下拉選擇新模板 → 重新解析並覆寫 textarea 內容，顯示 Toast 確認提示。

**字數/則數計算**

```
len = textarea.value.length
segments:
  len === 0        → 0
  len <= 70        → 1
  else             → ceil(len / 67)
```

**「確認發送」行為**

- `len === 0` → 按鈕 disabled。
- 點擊 → 呼叫 `POST /api/sms/send`（詳見後端規格）。
- 成功 → Toast「已發送」，關閉 Modal，更新格內簡訊送出標記。

### 2.3 簡訊模板設定頁

#### 2.3.1 頁面頂部：全域開關

| 開關 | 說明 |
|---|---|
| 發送預約簡訊 | 全系統開關，關閉時所有預約不發送簡訊 |
| 包含接受電訪推廣 | 附加條款，影響某些情境模板的適用對象 |

#### 2.3.2 三欄佈局（桌機）

```
┌───────────────┬──────────────────────────┬──────────────────┐
│  模板清單     │  模板編輯器              │  即時預覽        │
│  (300px)      │  (flex: 1)               │  (360px)         │
└───────────────┴──────────────────────────┴──────────────────┘
```

窄螢幕（`≤ 1100px`）：三欄垂直堆疊。

**左欄：模板清單**

- 搜尋框（依名稱、說明即時過濾）
- 「+ 新增模板」按鈕
- 分組顯示：⭐ 釘選 → 全部模板
- 每張模板卡片：名稱、說明、建立者/日期、釘選星號、啟用/停用 badge
- 系統內建模板（`id` 前綴 `b`）不可刪除

**中欄：模板編輯器**

| 欄位 | 型別 | 說明 |
|---|---|---|
| 模板名稱 * | text | 唯一名稱 |
| 說明 | text | 顯示在清單卡片上 |
| 簡訊內容 * | textarea | 可直接輸入或透過參數 chips 插入 |
| 參數插入 chips | 按鈕列 | 點擊插入 `{{參數}}` 到游標位置 |
| 啟用開關 | toggle | 停用模板不出現在預約頁下拉 |

操作按鈕：儲存 / 清除 / 刪除（自訂模板限定）

**右欄：即時預覽**

- 手機樣式氣泡，顯示解析後文字（以範例資料替換參數）
- 字數、預估則數
- 參數 token 以顏色標示（設定頁專屬，預約頁已移除）

## 三、系統參數定義

所有參數在「預約操作頁」套用時由系統自動帶入，不需人員手動填寫。

| 參數 Token | 來源 | 說明 |
|---|---|---|
| `{{會員姓名}}` | 預約資料 | 會員全名 |
| `{{門市名稱}}` | 門市設定 | 當前門市名稱 |
| `{{預約日期}}` | 預約資料 | 格式：MM/DD（星期） |
| `{{預約時間}}` | 預約資料 | 格式：HH:MM |
| `{{療程}}` | 預約資料 | 療程項目名稱 |
| `{{門市地址}}` | 門市設定 | 完整地址 |
| `{{門市電話}}` | 門市設定 | 含區碼，例：02-XXXX-XXXX |

## 四、前端 API 介面（待後端對接）

> 以下為前端需要的介面定義；詳細 Request/Response Schema 見後端規格書。

| 動作 | Method | 路徑 | 說明 |
|---|---|---|---|
| 取得模板清單 | GET | `/api/sms-templates` | 含系統內建 + 門市自訂 |
| 新增自訂模板 | POST | `/api/sms-templates` | |
| 更新模板 | PUT | `/api/sms-templates/:id` | |
| 刪除自訂模板 | DELETE | `/api/sms-templates/:id` | 系統內建不可刪 |
| 取得個人偏好 | GET | `/api/user/sms-preferences` | 釘選、最近使用、上次模板 |
| 更新個人偏好 | PUT | `/api/user/sms-preferences` | |
| 發送簡訊 | POST | `/api/sms/send` | 含預約 ID、最終簡訊文字、發送時間 |
| 取得門市設定 | GET | `/api/store/settings` | 發送簡訊開關、電訪開關 |
| 更新門市設定 | PUT | `/api/store/settings` | |

## 五、本機原型的持久化 Schema（localStorage）

> 原型階段使用 `localStorage`，上線版改為後端 API；key 命名供對應參考。

| Key | 型別 | 說明 |
|---|---|---|
| `npos_tpl_custom` | `JSON Array` | 自訂模板清單 |
| `npos_tpl_pins` | `JSON Array<string>` | 釘選模板 ID 清單 |
| `npos_tpl_recent` | `JSON Array<string>` | 最近使用（最多 5 筆） |
| `npos_tpl_last` | `string` | 上次套用的模板 ID |
| `npos_sms_enabled` | `"1"` / `"0"` | 全域簡訊發送開關 |
| `npos_sms_tele` | `"1"` / `"0"` | 電訪推廣開關 |

**模板物件結構**

```json
{
  "id": "c_1719374400000",
  "name": "標準預約提醒",
  "desc": "適用一般預約，含地址與電話",
  "body": "親愛的{{會員姓名}}您好，提醒您已預約{{門市名稱}}，日期：{{預約日期}} {{預約時間}}，地點：{{門市地址}}，如需更改請來電 {{門市電話}}。",
  "creator": "admin",
  "created": "2026-06-26",
  "enabled": true,
  "scenario": "預約簡訊"
}
```

## 六、互動驗收清單

### 預約操作頁
- [ ] 點擊空格 → 建立預約 Modal 開啟，床位與時段預填
- [ ] 存檔後依簡訊偏好決定是否開啟 SMS Modal
- [ ] 點擊已存在預約格 → 直接開啟 SMS Modal
- [ ] SMS Modal 開啟時自動套用上次模板，顯示「已沿用上次選擇」標籤
- [ ] 首次使用（無上次記錄）→ 套用第一筆啟用模板
- [ ] 切換模板下拉 → 更新 `lastId`、重新解析寫入 textarea、顯示 Toast
- [ ] 所有 `{{參數}}` 在 textarea 中已解析為實際文字（無 token 殘留）
- [ ] 字數即時計算；0 字時「確認發送」disabled
- [ ] 點「管理模板 ↗」→ 跳轉到模板設定頁
- [ ] 會員拒絕簡訊時顯示警示列，仍可強制發送

### 模板設定頁
- [ ] 新增模板、儲存後立即出現在清單與預約頁下拉
- [ ] 停用模板後不出現在預約頁下拉，但清單仍顯示（opacity 較淡）
- [ ] 點擊參數 chip → 插入游標位置（`{{參數}}`）
- [ ] 右欄即時預覽隨編輯更新
- [ ] 系統內建模板無「刪除」選項
- [ ] 全域開關切換 → 呼叫 API 更新，重整後狀態保留

## 七、邊界條件

| 情境 | 處理方式 |
|---|---|
| `localStorage` 被停用（沙箱） | `try/catch` 退回記憶體物件，功能正常但重整後歸零 |
| 模板被刪除但 `lastId` 仍指向它 | `tplById(lastId)` 回傳 null → 改用預設模板，不報錯 |
| textarea 送出時長度超過 670 字 | 顯示超額警示；允許送出（由人員決定） |
| API 失敗 | Toast 顯示錯誤訊息；Modal 不自動關閉 |
